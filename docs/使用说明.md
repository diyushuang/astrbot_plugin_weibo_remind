# 使用说明

本插件要做的事只有一件：**盯住一个微博账号，把它正文里写的时间变成群里的闹钟**。

---

## 1. 它怎么工作

```
每 N 秒抓一次时间线
   └─ 有新微博？
        ├─ 判形态：排期公告 / 声明打假 / 建议反馈 / 日常
        │     └─ 只有排期公告类才建提醒；其余静默（打假博里也有「行程」字样，别被带跑）
        ├─ 解析正文里的时间（三层：结构化 → 纯数字 → 中文语义）
        ├─ 每个时间点 × 每个提前档位 → 建一条待触发任务（存 SQLite）
        └─ 完全解析不出时间 且 属于排期公告类 → 推原文请群友确认
每 20 秒扫一次任务表
   └─ 到点 → 渲染提醒 → 推到所有绑定群（带不带 @全体 由四道闸门判定）
```

解析基准取**微博发布时间**而不是抓取时间——微博可能补发，用当前时间做基准会把
「今晚8点」误判成已过去。是否已过期另用当前时间判断。

## 2. 指令速查

| 指令 | 权限 | 用在什么时候 |
| --- | --- | --- |
| `微博提醒 帮助` | 所有人 | 忘了指令怎么写 |
| `微博提醒 绑定` | 所有人 | 在群里执行一次，本群开始收提醒 |
| `微博提醒 解绑` | 所有人 | 本群不再收提醒 |
| `微博提醒 状态` | 管理员 | 排障第一步：版本、监控账号（多个）、轮询、待触发、风控冷却、解析引擎与 LLM 兜底状态、免打扰时段与发送节流、词表过滤与周期续期开关、@全体 用量 |
| `微博提醒 列表` | 管理员 | 看接下来会推什么（触发时间 / 档位 / 命中原文 / 正文摘要） |
| `微博提醒 暂停` / `恢复` | 管理员 | 临时不抓也不推（已建任务保留，恢复后按补发处理） |
| `微博提醒 重抓` | 管理员 | 不想等下一轮，立即抓一次 |
| `微博提醒 测试 <时间文本>` | 管理员 | 怀疑解析不准时，直接喂一句话看解析结果 |
| `微博提醒 覆盖` | 管理员 | 看博文覆盖率与「待补样本」，判断有没有漏检 |
| `微博提醒 全体 开/关/状态` | 管理员 | 开关 @全体成员并查看限额用量 |

> 指令名不含空格。`微博提醒 测试 今晚8点开播，明天下午3点复盘` 会返回两个时间点。

## 3. 典型场景

### 场景一：追更排期公告

博主常在晚上发次日节奏，正文形如：

```
📢商务物料
⏰10月17日
10:00 邀约试驾视频
```

插件会为「10-17 10:00」按档位各建一条任务。若同时想提醒「10月18日 / 10月19日」那些行，
它们也会各自建任务——单条微博最多建 `max_tasks_per_post`（默认 3）个时间点，
想全覆盖就把它调大。

### 场景二：只关心到点那一刻，不要提前轰炸

- `remind_advance_minutes` 改成 `[0]`：只在事件到点时推一次；
- 想保留提前提醒但只 @ 到点那次：`at_all_advance_minutes` 保持默认 `[0]`。

### 场景三：重要内容才 @ 全体

```
微博提醒 全体 开
# 然后在配置面板里把 at_all_keywords 填成：直播 首播
# 并在 at_all_daily_limit 里控制每天最多炸几次（默认 5）
```

### 场景四：漏了怎么办

先 `微博提醒 覆盖` 看是不是「待补样本」。若确实漏了：

1. 拿微博原文，用 `微博提醒 测试 <时间片段>` 复现；
2. 若解析不出，多半是没覆盖的新写法——把「博主名 + 原文」提 Issue，
   我们会把它加进回归夹具（见 [CONTRIBUTING.md](../CONTRIBUTING.md) 第 8 节）；
3. 若解析对了但没建任务，看 `微博提醒 列表` 与日志：可能是时间已过去、
   或档位都已过（抓到时离事件不足 60 分钟，提前 60 档会静默跳过）。

## 4. 已知行为（不是 bug）

| 现象 | 原因 |
| --- | --- |
| 时间已过的微博不提醒 | 刻意设计：错误提醒比漏提醒更糟（不自动顺延 24 小时） |
| 裸 `1030` 不建任务 | 既能读成 10:30 也能读成 10月30日，无上下文时不猜 |
| `每周五晚8点` 只提醒最近一次 | 周期表达不做自动续期 |
| 早于抓取时间的那一档没推 | 该档已过，静默跳过 |
| 建议博 / 打假声明没有任何反应 | 形态分类判定为非排期公告类，静默是对的 |
| 重启后收到标着「补发提醒」的消息 | 宽限窗内（默认 10 分钟）错过任务的补偿；超期不再补 |
| 群里只看到正文、没有 @全体 | 带 @ 发送失败后自动降级重发（多数是机器人不是管理员） |

## 5. 排查清单

按顺序做，多数问题能在前三步定位：

1. **`微博提醒 状态`** —— 看「推送目标」「上次抓取」「风控冷却」「解析引擎」四行；
2. **看日志** —— 每条新微博都有一行结论（建了几条任务 / 为什么跳过）；
3. **`微博提醒 覆盖`** —— 排期类覆盖率若低于 100%，看「待补样本」里的原文；
4. **`微博提醒 测试 <时间文本>`** —— 判断是「没识别出时间」还是「识别对了但被策略跳过」；
5. **`微博提醒 列表`** —— 确认任务到底建没建、触发时间是什么。

日志关键词对照：

| 日志 | 含义 |
| --- | --- |
| `已创建 N 条提醒任务（时间点：…）` | 正常建任务 |
| `提到的时间都已过去或超出窗口，静默跳过` | 时间已过，符合预期 |
| `含 N 处纯数字时间上下文不足` | 纯数字歧义，刻意不建 |
| `排期类博文但未识别出时间，已推送原文` | 解析失败兜底，值得提 Issue |
| `触发微博风控，全局冷却 X 分钟` | 被微博限流，插件自动停抓一段时间 |
| `带 @全体 发送失败，改为不带 @ 重发` | 机器人无管理员权限或撞 @全体 频控 |
| `检查轮次异常（第 N 次）` | 单轮出错并退避，下一轮会继续 |
