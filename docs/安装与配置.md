# 安装与配置指南

本文覆盖从零安装到参数调优的全过程。只想快速跑起来，看 README 的「快速开始」即可。

---

## 1. 环境要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| AstrBot | ≥ 4.24，< 5 | 见 `metadata.yaml` 的 `astrbot_version`；不满足时 AstrBot 会拒绝加载并提示版本不兼容 |
| 协议端 | aiocqhttp（OneBot v11） | 本插件通过 AstrBot 主动发送群消息，仅声明支持 `aiocqhttp` |
| Python | **3.12+** | AstrBot ≥4.19.5 本身就要求 Python ≥3.12——用 3.10/3.11 连 AstrBot 都装不上，与本插件无关 |
| 网络 | 能访问 `m.weibo.cn` | 抓取走微博公开游客接口；必要时可配代理 |

> 机器人**不需要**是群管理员也能正常推送；只有 `@全体成员` 需要管理员权限。

---

## 2. 安装

### 方式一：插件市场（推荐）

AstrBot WebUI → `插件` → `插件市场` → 搜索「微博定时提醒」→ 安装 → 重载插件。
AstrBot 会自动读取 `requirements.txt` 安装 `aiohttp` 与 `jionlp`。

### 方式二：手动安装

```bash
cd <AstrBot 根目录>/data/plugins
git clone https://github.com/diyushuang/astrbot_plugin_weibo_remind
# 或把 astrbot_plugin_weibo_remind 目录直接拷进来
pip install -r astrbot_plugin_weibo_remind/requirements.txt
```

然后在 WebUI 的插件页点 `重载插件`。

### 关于 jionlp

`jionlp` 负责中文自然语言时间（`今晚8点`、`明天下午3点`、`每周五晚8点`）。
**未安装时插件仍能正常加载**，只是这一类表达解析不了，仅剩「结构化」与「纯数字」两层，
启动日志会给出提示。想确认它是否生效：群里发 `微博提醒 状态`，看「解析引擎」一行。

## 3. 最小可用配置

1. **确认监控账号**：配置项 `uids`（列表）默认 `["6902546888"]`（本项目实测账号），
   换成你要盯的账号：打开其微博主页，`weibo.com/u/` 后面那串数字就是 uid。
   可以填多个，每个账号独立去重、独立判定首轮基线；旧字段 `uid` 仍会被读取并合并。
2. **绑定接收群**：在目标群里发送 `微博提醒 绑定`（把该会话写入 `push_sessions`）。
   不方便在群里发指令时，也可以手工填 `push_group_ids` + `default_platform`。
3. **确认能收到**：等账号发新微博，或发 `微博提醒 重抓` 立即抓一轮；
   用 `微博提醒 状态` / `微博提醒 列表` 观察结果。

首轮启动会把当前可见微博全部记为已见（防止历史博文刷屏），但**时效窗口内**的仍会被解析——
所以刚装好当天的「明天下午3点」不会漏。

## 4. 配置项详解

按重要性排序。全部字段见插件配置面板（`_conf_schema.json`）。

### 4.1 抓取

| 字段 | 默认 | 怎么调 |
| --- | --- | --- |
| `uids` | `["6902546888"]` | 监控账号列表，可填多个；旧字段 `uid` 自动合并。改完需重载插件 |
| `poll_interval` | `120` | 轮询间隔（秒，最小 30）。间隔越小越及时，但触发微博风控的概率越高 |
| `check_window_minutes` | `720` | 只处理发布后此分钟内抓到的微博。作用是防止首轮补看或翻页补漏时把陈年旧博当新提醒；`0` = 不限 |
| `custom_cookie` | 空 | 留空走游客身份（推荐）。填写后启用登录态，可看到与登录浏览器一致的可见范围，**深翻历史分页也必须靠它** |
| `proxy` | 空 | 海外/VPS 部署建议配国内出口代理，显著降低风控概率 |
| `request_timeout` | `15` | 单请求超时（秒） |

### 4.2 时间解析

| 字段 | 默认 | 怎么调 |
| --- | --- | --- |
| `date_only_default_hour` | `9` | 只有日期没有时刻时（如「10月30日发售」）用几点提醒。jionlp 对纯日期默认给当天 0 点，凌晨提醒通常不合适 |
| `max_future_days` | `60` | 超过此天数的时间点不建任务（防误解析出很远的日期） |
| `max_tasks_per_post` | `3` | 单条微博最多建几个时间点。排期体一条可能列了十几个时间，全建会淹掉群 |
| `text_max_length` | `500` | 推送/快照的正文截断长度 |
| `debug_parse` | `false` | 打开后每条微博的解析候选明细写进日志，排查解析问题用 |

### 4.3 词表与兜底解析

| 字段 | 默认 | 怎么调 |
| --- | --- | --- |
| `include_keywords` | `[]` | 只处理含任一关键词的博文（空 = 不限）。与形态分类叠加生效 |
| `exclude_keywords` | `[]` | 命中任一即整条静默，优先于 include。适合屏蔽「抽奖」「转发」 |
| `llm_fallback` | `false` | 规则三层都解析不出、且博文是排期类时，调用 AstrBot 的 LLM 再抽一次 |
| `llm_provider_id` | 空 | 指定 provider；建议用便宜、快的模型专做抽取 |
| `llm_timeout_seconds` | `25` | 单次调用超时；连续 3 次失败后本次运行不再调用 |

LLM 的输出必须过四道校验（可解析 / 年份合理 / 不早于发布且不超 `max_future_days` /
**引用的原文必须真的在正文里**）才会建提醒，编造的时间一律丢弃；
兜底失败时行为与未开启完全一致（排期类推原文、其它静默）。

### 4.4 免打扰与发送节流

| 字段 | 默认 | 怎么调 |
| --- | --- | --- |
| `quiet_hours` | 空 | `HH:MM-HH:MM`（支持跨午夜，如 `23:00-08:00`）。时段内到点的提醒顺延到时段结束并标注「顺延提醒」；解析失败提示这类非定时消息直接跳过 |
| `push_jitter_seconds` | `0` | 每条提醒发送前随机延迟 0~N 秒。易被风控的部署建议 `5~30` |
| `push_interval_seconds` | `0` | 同批到期任务之间的发送间隔。建议 `2~5` |
| `recurrence_renew` | `true` | 「每周X」「每天」类提醒发送后自动续建下一期；关掉则只提醒最近一次 |
| `cookie_fail_alert_after` | `3` | 自定义 Cookie 连续失败多少次后群告警（多账号各计一次），`0` = 不告警 |

### 4.5 提醒档位

`remind_advance_minutes` 默认 `[60, 10, 0]`：每个识别出的时间点，按每档各推一次
（`0` = 到点）。抓到微博时已经过去的档位会静默跳过。

> 档位越多，群里消息越多。追更场景常用 `[60, 0]` 或 `[10, 0]`。

### 4.6 @全体成员

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `at_all` | `false` | 总开关，也可用 `微博提醒 全体 开/关` 动态切换 |
| `at_all_advance_minutes` | `[0]` | **只对这些档位 @**。默认只有到点档——多档全 @ 会连炸三次群 |
| `at_all_keywords` | `[]` | 非空时仅命中关键词才 @ |
| `at_all_daily_limit` | `5` | 每日上限，超限自动降级为普通提醒；`0` = 不限 |

前提：机器人在目标群需要有管理员权限，否则 QQ 不允许发 @全体。
插件检测到带 @ 发送失败会自动去掉 @ 重发一次，保证正文一定到群。

### 4.7 推送与异常

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `push_sessions` | `[]` | 推送目标，由 `微博提醒 绑定` 自动写入 |
| `push_group_ids` | `[]` | 手工填群号，配合 `default_platform` 拼会话标识 |
| `default_platform` | `aiocqhttp` | 平台实例 ID |
| `push_on_parse_fail` | `true` | 排期类博文完全解析不出时间时，推原文请群友确认；关闭则只记日志 |
| `remind_template` | 见面板 | 提醒文案模板，占位符 `{name}{source}{event_time}{advance}{weibo}{link}` |
| `parse_fail_template` | 见面板 | 解析失败文案模板 |
| `message_send_timeout` | `60` | 单条推送超时（秒），防适配器卡死拖住调度 |
| `missed_remind_grace_minutes` | `10` | 插件/AstrBot 重启后，错过的提醒在多少分钟内补发（会标注「补发提醒」）；超期标记为 missed 不再推送 |

### 4.8 模板占位符

| 占位符 | 含义 |
| --- | --- |
| `{name}` | 博主昵称 |
| `{source}` | 正文里命中的时间原文（如 `10月17日 10:00`） |
| `{event_time}` | 事件本身的时间（`YYYY-MM-DD HH:MM`） |
| `{advance}` | 提前档位（到点档显示「到点」） |
| `{weibo}` | 微博正文 |
| `{link}` | 原微博链接 |

模板里写 `\n` 表示换行。占位符缺失时原样保留，不会报错。

## 5. 目录与数据

| 路径 | 内容 |
| --- | --- |
| `data/config/astrbot_plugin_weibo_remind_config.json` | 插件配置（AstrBot 管理） |
| `data/plugin_data/astrbot_plugin_weibo_remind/weibo_remind.db` | SQLite：已见微博、提醒任务、@全体 计数 |
| 同目录 `coverage.json` | 覆盖自检统计（跨重启累计） |
| 同目录 `uncovered.jsonl` | 「排期公告类但没建出任务」的待补样本 |

数据全部落在 AstrBot 的 data 目录，**不写插件自身目录**——更新/重装插件不会丢数据。

## 6. 常见安装问题

**Q：插件加载失败，提示版本不兼容？**
`metadata.yaml` 声明了 `astrbot_version: ">=4.24,<5"`。升级 AstrBot，或在 WebUI 安装时
选择「无视警告，继续安装」（不推荐在 v5 上跑，未做过验证）。

**Q：装完没有任何反应，群里什么都不发？**
按顺序查三件事：① `微博提醒 状态` 看「推送目标」是否为 0（是 0 就说明还没绑定）；
② 看「上次抓取」是否有时间戳、日志里有没有风控提示；③ 确认监控账号确实在发新微博。
`微博提醒 重抓` 可以立即触发一轮，不用等轮询间隔。

**Q：解析引擎显示「不可用（降级）」？**
jionlp 没装上。`pip install jionlp` 后重载插件。

**Q：想换监控账号 / 加一个账号？**
改 `uids` 后重载插件。已见记录按账号（uid）分别记录，新加账号首轮只建自己的基线，
不会把它的历史博文当成新提醒；也不会因为它自己「没有记录」而重刷已有账号的历史。

**Q：`custom_cookie` 怎么取？**
浏览器登录微博 → 打开开发者工具 → Network → 任意请求 → 复制请求头里的 Cookie 整串。
它相当于你的登录凭据，配置面板已按 `secret` 处理（仅遮罩显示），但配置文件本身是明文，
请自行保护 AstrBot 数据目录权限。Cookie 失效时按「自定义 Cookie 已失效」记录日志，
需你自行更换。连续失效达到 `cookie_fail_alert_after`（默认 3 次）后，插件会往推送目标
发一条更换提醒（每天最多一次），避免群友误以为「博主没发微博」。
