## 三、_conf_schema.json

- 21 个字段，`type` 全部取自规范允许集合：`string` / `text` / `int` / `float` / `bool` / `object` / `list`；
- 每个字段都有 `description` 与 `default`，复杂项带 `hint`；
- 敏感项 `custom_cookie`、`proxy` 均标 `secret: true`（规范明确要求 API Key / 令牌类字段这么做）。

## 五、本轮（v0.3.1）具体调整与原因

### 5.1 目录与文件

| 调整 | 原因 |
| --- | --- |
| 新增 `LICENSE`（MIT） | 规范要求遵守并保留开源许可；GitHub 仓库也需要许可证文件。内容与作者其它仓库一致（`Copyright (c) 2026 diyushuang`） |
| 新增 `CONTRIBUTING.md` | GitHub 仓库规范；也是本仓库"唯一规范出处"：目录/代码/测试/提交信息/分支/发版流程 |
| 新增 `SECURITY.md` | GitHub 推荐；声明威胁模型与已知设计取舍，避免把"刻意设计"当漏洞上报 |
| 新增 `.github/ISSUE_TEMPLATE/`（bug / feature / config） | 用模板强制收集复现要素（版本、原文、日志），本类问题没有原文就无法复现 |
| 新增 `.github/workflows/tests.yml` | CI 跑 ruff 与 pytest，避免"本地绿、提交红" |
| 新增 `docs/安装与配置.md`、`docs/使用说明.md` | 把 README 里过长的安装/配置/排障内容下沉，README 保持可读 |
| 新增 `docs/规范符合性说明.md` | 即本文件：把规范条目与落实位置一一对应，便于复查 |
| 新增 `logo.png`（256×256） | 规范推荐；插件市场列表里更容易辨认 |
| 新增 `dev_requirements.txt` | 把开发依赖与运行期依赖分开，安装插件时不会把 pytest/ruff 带给用户 |
| 新增 `.gitattributes` | 统一行尾为 LF，避免 Windows 提交造成整文件 diff |
| 重写 `.gitignore` | 对齐作者其它仓库：覆盖缓存、虚拟环境、打包产物、本地工具目录与敏感文件 |
| 移动「博文覆盖分析报告」到 `docs/` | 它是项目文档，放在仓库里才自洽（原先散落在仓库外） |
| `requirements.txt` 补版本约束 | 原先只有裸 `jionlp`；现按仓库惯例写 `aiohttp>=3.9,<4`、`jionlp>=1.5,<2` |

### 5.2 代码

| 调整 | 原因 |
| --- | --- |
| `coverage.py` → `post_coverage.py` | **与 PyPI 上极常见的 `coverage` 包同名**（pytest-cov 的依赖）。AstrBot 内以相对导入加载不受影响，但扁平导入（本地脚本、测试、第三方工具）下可能被抢先解析到另一个包。改名消除歧义，行为完全不变 |
| 同步更新 `main.py` 与测试的导入、README/文档中的引用 | 跟随上一条 |
| 集成用例与包路径用例关掉后台调度循环 | 测试竞态：`initialize()` 拉起的常驻调度循环**启动即扫一次**，会与用例手动的 `scan_once()` 抢任务，导致断言偶发失败（全量跑约 1/4 概率）。夹具里置空该循环后用例只手动驱动；**产品行为不变**（线上只有这条循环） |

### 5.3 文档

| 调整 | 原因 |
| --- | --- |
| README 增加许可证徽章、AI 生成徽章与「AI 生成声明」 | 与作者其它仓库一致；说明代码由 AI 生成，使用者应自行评估风险 |
| README 增加「目录结构」「常见问题」「贡献」「许可证」章节 | GitHub 仓库规范；原先缺少"找得到文档"的入口 |
| README 的模块引用更新为 `post_coverage` | 跟随 5.2 |
| CHANGELOG 增加 v0.3.1 条目 | Keep a Changelog 格式，中文条目 |

### 5.4 未改动的部分（刻意保留）

- **`metadata.yaml` 的 `repo` 与仓库地址**：仍指向 `github.com/diyushuang/astrbot_plugin_weibo_remind`，
  若你尚未创建该仓库需先建，否则插件市场的源码链接会是死链（规范第 4 节要求 repo 可用）。
- **`support_platforms` 只声明 `aiocqhttp`**：本插件靠 OneBot 的群消息与 at_all 段工作，
  声明更多平台属于虚假声明。
- **功能行为一律不变**：本轮只动结构、文档与模块名，解析规则、策略判定、推送文案、
  配置项与指令**全部保持原样**（见下一节的验证）。

## 六、行为不变的验证方式

结构调整最怕"顺手改坏行为"。本轮的验证办法：

1. **全量用例**：改动前后均为 `206 passed, 10 skipped`，且连续 5 次全量运行无偶发失败；
2. **真实语料决策复核**：用 98 条真实博文跑「分类 + 解析 + 决策」全流程，
   改动前后的输出**逐行 diff 为 0 处差异**（建任务 77 / 静默 20 / 时间已过 1 / 推原文 1，
   排期类覆盖率 98.7%）；
3. **真实加载**：按 AstrBot 包路径（`data.plugins.<插件名>`）在隔离子进程里加载并跑通
   「建任务 → 调度 → 渲染推送」，含 @全体 段断言；
4. **版本号四处同步**：`metadata.yaml` / `constants.py` / `CHANGELOG.md` / README 徽章。

复现命令：

```bash
python -m pytest -q                     # 206 passed, 10 skipped
ruff check . && ruff format --check .   # 干净
```
