定时抓取**多个**指定微博账号的新微博，**自动解析正文里的中文时间描述**，按配置的提前档位
把内容推送到 QQ 群。适合追更「发布节奏 / 行程同步 / 直播预告」这类排期体微博——
博主在正文里写「今晚8点」「明天下午3点」「10月17日 10:00」，插件替你在到点前闹钟。

📖 详细文档：[安装与配置指南](docs/安装与配置.md) ｜ [使用说明](docs/使用说明.md) ｜ [博文覆盖分析报告](docs/博文覆盖分析报告.md) ｜ [规范符合性说明](docs/规范符合性说明.md) ｜ [发布前检查清单](docs/发布前检查清单.md)

## 特性

- **多账号监控**：`uids` 填多个 UID 同时盯，每个账号独立去重、独立判首轮基线
- **三层时间解析**（结构化 + jionlp + 纯数字），覆盖真实排期体微博的写法：
  `⏰10月17日 / 10:00 邀约试驾视频`、`【0945】开播预告`、`0711发布节奏`、`【623发布节奏】`、
  `12.03发布计划`、`今晚8点`、`明天下午3点`、`1030上线`（4 位数字按前后文判断是时刻还是日期）
- **博文形态分类**：先判断这条博文是「排期公告 / 声明打假 / 建议反馈 / 日常」，
  再决定处理方式。声明与建议博一律静默——实测 98 条真实博文里有 20 条是这类，
  它们含「月」「行程」等字样，按「有没有时间信号」判会被当成解析失败推给群友，纯噪音
- **覆盖自检**：每条博文的处理结果留档统计，`微博提醒 覆盖` 随时看覆盖率与待补样本
- **用户词表**：`include_keywords` / `exclude_keywords` 按关注的词收窄或屏蔽博文
- **LLM 兜底**（可选）：规则解析不出时用 AstrBot 的 LLM 再抽一次，输出过四道校验才建提醒
- **周期续期**：「每周五」「每天」类提醒发送后自动续建下一期（可关）
- **Cookie 失效告警**：自备 Cookie 连续失效会在群里提醒更换，不再静默漏抓
- **多档提醒**：默认提前 60 分钟、提前 10 分钟、到点各推一次，档位可配
- **免登录抓取**：走 m.weibo.cn 的公开游客接口，不需要你的微博账号 Cookie
- **重启不丢任务**：任务存 SQLite，重启后宽限窗内错过的提醒会带「补发」标记补推
- **风控自保**：IP 级风控（418/432/返回 HTML）自动进入全局冷却，冷却期内不再出网
- **免打扰时段**：`23:00-08:00` 内到点的提醒顺延到时段结束并标注，不深夜炸群也不漏提醒

## 安装

1. 把 `astrbot_plugin_weibo_remind/` 放进 AstrBot 的 `data/plugins/` 目录
   （或在插件市场搜索安装）。
2. 安装依赖：`pip install jionlp`
   - 未安装时插件仍可正常加载，只是**中文自然语言时间**（今晚8点/明天下午3点）
     解析不了，仅剩结构化与纯数字两层，启动日志会给出提示。
3. 在 AstrBot 管理面板的插件配置里确认 `uids`（可填多个账号），重启插件。

## 快速开始

```
# 1. 在要接收提醒的群里绑定
微博提醒 绑定

# 2. 想确认解析效果，先拿一句话试
微博提醒 测试 今晚8点开播，明天下午3点复盘

# 3. 查看监控账号、待触发任务与运行状态
微博提醒 状态
微博提醒 列表
```

## 博文覆盖机制

「覆盖所有博文」不是靠堆正则，而是**先分类、再决定怎么处理**，并且把结果留档，
让没覆盖到的情况能自己浮出来。

### 一、博文形态分类（`post_coverage.classify_post`）

| 形态 | 判据（命中即止，顺序即优先级） | 处理 |
| --- | --- | --- |
| 建议反馈 | 建议博 / 反馈 / 留言 / 私信 | 静默 |
| 声明打假 | 网传 / 为假 / 请勿 / 声明 / 谢绝 / 辟谣 | 静默 |
| 排期公告 | 发布节奏 / 物料 / 官宣 / 预告 / 海报 / 行程同步 / 直播…，或出现结构化时间标记（⏰、【HHMM】、X月X日、HH:MM） | 建提醒；完全解析不出时间 → 推原文请群友确认 |
| 日常其他 | 其余 | 静默 |

顺序很重要：打假博文里同时有「行程」「通知」等排期词（实测
「网传活动行程为假，请大家以官方通知为准」），排期判定放在声明之后才不会误判。

### 二、覆盖自检（`post_coverage.CoverageTracker` + `微博提醒 覆盖`）

- 每条博文记录：形态、处理结果（已建任务 / 推原文 / 时间已过 / 数字歧义 / 静默）、
  建任务数、原因、正文摘要；
- 统计口径：**覆盖率 = 建出提醒 ÷（建出提醒 + 待补）**。注意分母**不含**「时间已过」
  的博文——停机后补看历史博文时这类很多，算进去会让覆盖率无故掉到 0%，看不出真实水平；
  「微博提醒 覆盖」里会把「时间已过正确跳过」单独列出来；
- 只有真正的覆盖缺口（排期公告类没建出任务、又不是因为时间已过）才记入待补样本，
  追加到数据目录的 `uncovered.jsonl`，并可通过指令查看，照样本补规则即可持续提升覆盖；
- 结果落盘 `coverage.json`（跨重启累计）。

### 三、实测覆盖情况（UID 6902546888 的 98 条真实博文）

| 指标 | 结果 |
| --- | --- |
| 排期公告类 | 78 条 |
| 其中建出提醒 | 77 条 |
| 覆盖率 | **98.7%** |
| 推原文（时间待定） | 1 条（「10月24日 官宣杀青物料 / 具体发布待定」，时间未定无可建） |
| 待补样本 | 0 条 |
| 正确静默 | 20 条（建议博 8、打假声明 5、日常 7） |

> 抓取边界：免登录单页最多取到 **98 条**（`count=200` 封顶），深翻分页（`page>=2`）
> 会被要求登录。该账号 `total=288`，即约 190 条更早的历史需要登录态才能取。
> 若需要这部分历史，可在配置里填 `custom_cookie`（用自己的微博 Cookie）。
>
> 也因此，插件每轮实际只能看到单页那批（默认 `count=50` → 48 条）：翻页补漏只在
> 配了 `custom_cookie` 的部署上才有意义，游客身份下第 2 页必然失败——这种情况按
> 「没有更早的微博了」处理，不会丢掉本轮已抓到的内容。

## @全体成员

到点提醒可以 @全体成员，但直接「每条都 @」会踩三个坑：多档提醒连炸三次群、
QQ 对 @全体 有频率限制、机器人在群里不是管理员时协议端可能**整条拒收**（正文也发不出去）。
所以做成四道闸门逐级放行：

| 闸门 | 判定 | 不满足时 |
| --- | --- | --- |
| 1. 会话类型 | 必须是群聊（`GroupMessage`） | 私聊永远不 @ |
| 2. 总开关 | `at_all` 开启，或用 `微博提醒 全体 开` 动态打开 | 普通推送 |
| 3. 档位/关键词 | 命中 `at_all_advance_minutes`（默认只有到点档）与 `at_all_keywords`（空=不限） | 普通推送 |
| 4. 每日限额 | 今日 @ 次数 < `at_all_daily_limit`（默认 5） | 降级为普通提醒，内容照发 |

- **失败自动降级**：带 @ 发送失败（不是管理员 / 撞频控）时，自动去掉 @ 段重发一次，
  保证提醒正文一定到群；降级成功的那次不记 @ 次数。
- **计数**按上海时区自然日重置，存 SQLite，跨重启累计；`微博提醒 状态` 与
  `微博提醒 全体 状态` 都能看到「今日已用 N 次」。
- 解析失败提示（推原文那类）**不带** @全体——它不是到点事件。
- 前提：机器人在目标群需要有**管理员权限**，否则 QQ 不允许普通成员发送 @全体。

```
微博提醒 全体 开      # 打开（到点档才 @）
微博提醒 全体 状态    # 看档位限定 / 关键词 / 每日上限 / 今日已用
微博提醒 全体 关      # 关闭
```

## 时间解析规则

解析基准取**微博发布时间**而不是当前时间：微博可能补发，用当前时间做基准会把
「今晚8点」这类表达误判成已过去。是否已过期另用当前时间判断。

| 正文写法 | 结果 | 负责的层 |
| --- | --- | --- |
| `⏰10月17日` 换行 `10:00 邀约试驾视频` | 10-17 10:00 | 结构化（把裸时刻归属到前一行日期） |
| `【0945】开播预告` | 当天/最近日期 09:45 | 结构化（括号内 HHMM；【1700】=17:00，不会读成公元 1700 年） |
| `9:29 悬念海报` | 归到最近的日期上下文 | 结构化 |
| `9月7日` 换行 `11:00 平面预告` | 09-07 11:00 | 结构化 |
| `0711重要发布节奏` | 07-11（紧凑 MMDD） | 结构化 |
| `【623发布节奏】` | 06-23（括号内 3 位 + 排期词） | 结构化 |
| `12.03发布计划` | 12-03（带分隔符） | 结构化 |
| `📢新商务官宣 / 7:28 发布…`（当天 16:01 发布） | 次日 07:28 | 结构化（前夜发次日排期的裸时刻顺延） |
| `今晚8点` / `晚上8点半` | 当天 20:00 / 20:30 | jionlp |
| `明天下午3点` / `后天上午9点` | 对应日期 15:00 / 09:00 | jionlp |
| `今晚八点`（中文数字） | 当天 20:00 | jionlp |
| `双11上午10点` | 11-11 10:00 | jionlp |
| `明日10点` | 次日 10:00（同日纯日期候选去重） | jionlp |
| `每周五晚8点` | 最近一个周五 20:00（周期表达只提醒最近一次） | jionlp |
| `晚上8点到10点` | 20:00（区间取起点） | jionlp |
| `10月30日发售`（只有日期） | 10-30 09:00（默认时刻） | 两层合并 |
| `1030开播/直播` | 当天 10:30 | 纯数字（时刻上下文） |
| `1030上线/发售/开售/预售` | 10-30 09:00 | 纯数字（日期上下文） |
| `20261030上线` | 10-30 09:00 | 纯数字（8 位） |
| `1030`（无任何上下文） | 不建任务，记日志 | 歧义判定 |
| `#1030# 第1030期 每人1000元` | 不建任务 | 噪音剔除 |

## 异常处理

| 情况 | 处理 |
| --- | --- |
| 抓取网络超时 / 连接失败 | 单请求重试 3 次，整轮失败按 60→120→…→600 秒退避，只记首错防刷屏 |
| HTTP 418/432、JSON 接口返回 HTML | 判定 IP 级风控 → 全局冷却 10/30/60 分钟梯度，冷却期内不出网 |
| 接口 `ok=-100`（游客身份过期） | 自动向游客系统换新身份重试一次；续期节流 3 次/小时 |
| 自定义 Cookie 失效 | 直接报错并提示更换（不换游客身份，换了也没用） |
| 没有新微博 | 静默，不落盘不推送 |
| 建议博 / 打假声明 / 日常博 | 静默（按博文形态分类判定，不推原文——实测这类占 20/98） |
| 排期类博文完全识别不出时间 | 推送原文，提示群友自行确认（可用 `push_on_parse_fail` 关闭） |
| 排期类 + 明说「时间待定」 | 推送原文（时间未定，但让群友知道有这个安排） |
| 解析出的时间已过去 | 静默跳过，只记日志（不顺延——错误提醒比漏提醒更糟） |
| 到点时正处免打扰时段 | 顺延到时段结束并标注「顺延提醒」，状态仍是待触发（重启不会被判作废） |
| 免打扰时段内要推解析失败提示/Cookie 告警 | 跳过并记日志（非定时消息顺延无意义，隔夜推送只是噪音） |
| 纯数字歧义（如裸 `1030`） | 不建任务，记日志（不推送，避免噪音） |
| 单条推送失败/超时 | 标记 `failed`，**不自动重试**（避免「实际已送达却判超时」造成重复推送） |
| 插件/AstrBot 重启 | 中断在发送中的任务复位为待触发；宽限窗内错过的补推并标注「补发提醒」，超期标记 `missed` |
| 首次运行 | 把当前可见微博全部记为已见（防历史帖刷屏），但**时效窗口内的仍会解析**，装好插件当天的公告不会漏 |
| 微博被博主删除 | 不做额外检测，任务按建任务时存下的快照照常推送（链接可能 404） |
| jionlp 未安装 | 插件照常加载，自然语言层降级，启动日志提示 `pip install jionlp` |
| 单条博文解析异常 | 三层各自独立容错，任一层出错只丢该层结果，不影响其它博文建任务 |
| jionlp 解析出越界年份（如把【1700】读成公元 1700 年） | 丢弃该候选并做时间戳安全兜底，绝不因单条数据打断整轮 |

## 局限与已知约束

- **周期续期只覆盖「每周 X」与「每天」**：`每月 X 日` 不续期（月份天数不一致，边界容易算错），`每周五晚8点` 这类会按 7 天自动续建下一期，可在配置里关掉。
- **只能看到移动端公开可见的微博**：m.weibo.cn 游客接口看不到仅粉丝可见/已删除的内容。
- **免登录只能取到最近 98 条**：更早的历史（该账号约 190 条）需要登录态，可填 `custom_cookie`。
- **纯数字有歧义就不猜**：`1030` 既可能是 10:30 也可能是 10月30日，没有上下文时宁可不建任务。
- **站点抓取是串行的、全局共享风控状态**：多个账号按配置顺序逐个抓，账号间仍保持
  2~5 秒随机请求间隔；账号越多单轮越慢，轮询间隔要相应放宽。
- **推送目标是全局的**：绑定到哪些群就全部接收，暂不支持按账号分别路由到不同群。
- **已过的档位不补**：抓到时离事件不足 60 分钟，提前 60 分钟那一档就静默跳过了。
- 内容与图片都不落盘到插件目录，任务数据存 AstrBot 的 `data/plugin_data/astrbot_plugin_weibo_remind/`。

## 数据与隐私

- 不需要、也不会使用你的微博账号凭据；默认走匿名游客身份（可自愿填 `custom_cookie`，明文存于 AstrBot 插件配置）。
- 落盘内容：已见微博 id、任务快照（博主昵称、正文摘要、链接、命中时间原文）。不外发任何数据。

## 常见问题

**Q：装好了，群里什么都不发？**
按顺序查三件事：① `微博提醒 状态` 看「推送目标」是不是 0——是 0 说明还没在群里发过
`微博提醒 绑定`；② 看「上次抓取」有没有时间戳、日志里有没有风控冷却提示；
③ 确认监控账号确实发了新微博。`微博提醒 重抓` 可以不等轮询间隔立即抓一轮。

**Q：为什么这条微博没提醒？**
先 `微博提醒 测试 <正文里的时间片段>` 看是不是没解析出来：
- **解析不出** → 多半是新写法没覆盖，把原文提到 Issue 即可加进回归夹具；
- **解析对了但没建任务** → 看日志结论：时间已过去、档位都已过、或纯数字有歧义（刻意不建）。
- 也可能是**形态判定**：建议博 / 打假声明这类与提醒无关的博文会被静默，
  它们含「月」「行程」字样但确实不是时间安排；
- 还可能是**词表过滤**：检查 `include_keywords` 是否要求了没出现的词、
  或 `exclude_keywords` 是否命中了这条博文。

**Q：为什么有的微博提醒了，有的没提醒？**
看 [博文覆盖机制](#博文覆盖机制)——只有「排期公告类」才会建提醒，其余形态静默。
`微博提醒 覆盖` 能看到每一类的计数、覆盖率与待补样本。

**Q：@全体成员不生效，或者炸群太频繁？**
机器人需要在目标群有**管理员权限**，否则 QQ 不允许发 @全体（插件会自动去掉 @ 重发，
保证正文到群）。频次由 `at_all_advance_minutes`（默认只有到点档）与
`at_all_daily_limit`（默认 5 次/天）两道闸门控制，详见 [@全体成员](#全体成员)。

**Q：时间已经过去的那条为什么还要推？**
不会推。解析出的时间已过去会静默跳过（只记日志），**不自动顺延 24 小时**——
错误提醒比漏提醒更糟。重启后宽限窗内错过的任务会补推，并在消息里标注「补发提醒」。

**Q：首轮启动为什么把历史微博都记成"已见"了？**
防止把陈年旧博当成新提醒刷屏。但**时效窗口内**（默认 12 小时）的微博仍会被解析，
所以刚装好插件当天的「明天下午3点」不会漏。

**Q：想让它看到更早的历史微博（翻页）？**
m.weibo.cn 对 `page>=2` 一律要求登录，游客身份只能看单页（默认 48 条）。
需要深翻历史就配 `custom_cookie`：翻页本身仍是容错的，第 2 页失败不会丢掉第 1 页已抓到的内容。

**Q：解析引擎显示「不可用（降级）」？**
没装 jionlp。`pip install jionlp` 后重载插件；未装时插件仍可用，只是
「今晚8点」这类中文自然语言时间解析不了。

更多排障步骤见 [使用说明](docs/使用说明.md) 的「排查清单」。

   **导入相关改动还必须跑 `tests/test_package_load.py`**（它在子进程里按真实加载方式验证）；
3. 新用例要用故障注入自证有效，并把断言数写进 CHANGELOG。
